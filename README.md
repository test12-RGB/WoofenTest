# WoofenTest

> Woofen 专项 BUG 记录仓 —— **每条 BUG 一个 Issue**，方便检索、分级和回归验证。

## 数据来源

- Issues 由飞书「BUG 登记表」导入，共 **90 条**（导入时间 2026-11-17），序号与原表一致。
- 序号 ↔ Issue 编号对照见 [`docs/BUG导入对照表.md`](docs/BUG导入对照表.md)。
- 责任人字段在本仓库中脱敏为「姓**」。
- 已通过回归验证（验证 PASS）及判定为非问题／重复的条目已按原表状态关闭。

## 快速开始

1. 点 **Issues → New issue**，选择「BUG 报告」模板。
2. 标题统一格式：`[模块] 一句话现象`，例如 `[睡眠] 跨零点后睡眠分期丢失`。
3. 按模板填全：严重等级、设备与版本、复现步骤、期望 vs 实际、附件。
4. 开单前先在 Issues 里搜关键词，**同一个问题不要重复开单**，有新信息就追加评论。
5. 修复后回归通过再关闭，并在评论里写明「验证版本 + 验证结论」。

## 严重等级

| 等级 | 判定标准 | 处理时效 |
| --- | --- | --- |
| P0 | 主流程阻塞、崩溃、数据错误或安全风险 | 当天响应 |
| P1 | 核心功能异常，存在规避方案 | 本迭代内修复 |
| P2 | 一般功能问题，体验明显受损 | 排期修复 |
| P3 | 文案、UI 细节、优化建议 | 有空再处理 |

## 目录约定

| 路径 | 用途 |
| --- | --- |
| `.github/ISSUE_TEMPLATE/bug_report.md` | BUG 报告模板（新建 Issue 时自动带出） |
| `docs/` | 测试计划、用例表、版本回归结论 |
| `assets/` | 截图、日志、录屏等附件；大文件建议压缩后上传，正文里用相对路径引用 |

## 常用标签

| 标签 | 含义 |
| --- | --- |
| `bug` | 缺陷单（模板默认带上） |
| `P0` `P1` `P2` `P3` | 严重等级，便于按优先级筛单 |
| `regression` | 回归中发现的问题 / 老问题复现 |
| `blocked` | 被其他问题或环境阻塞，暂时无法推进 |
| `fixed-pending-verify` | 开发已修复，等待回归验证 |
| `invalid` | 确认不是问题（如 B14~B17 类误报） |

## 约定

- **一个 Issue 只描述一个问题**，多个问题拆成多条。
- 附件命名建议 `日期_模块_现象`，例如 `20261117_睡眠_分期丢失.mp4`。
- 关闭前必须回填「回归验证」段落，避免"修了但没验"。
