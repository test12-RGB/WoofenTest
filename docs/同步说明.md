同步引擎：`tools/woofen_sync.py`（无外部依赖，调用 `lark-cli` 读写多维表格、`gh` 读写 Issues）。

| 对象 | 坐标 |
| --- | --- |
| 飞书 Base | `Oo7LbHcD0aPFDCsYqeCc4jHEnnb` |
| 数据表 | `tblIVSPELHJJidVJ`（BUG登记表） |
| GitHub 仓库 | `brainvue-tech/TestBug`（私有；旧仓库 `test12-RGB/WoofenTest` 已停用） |

## 跑一轮会做什么

1. **新增**：飞书里新出现的记录（无对应 Issue）→ 自动创建 Issue，标题 `序号 + 简写问题`，正文含基本信息表与描述原文。
2. **内容同步**：飞书记录内容变化（描述、等级、版本、责任人、日期等）→ 覆盖更新对应 Issue 的标题与正文。
3. **状态同步**：按“谁改的谁说了算”处理，规则见下表。
4. **对齐校验**：即使本地状态文件丢失（例如换机器/新会话），脚本也会先按 Issue 正文里的隐藏标记 `woofen-sync:<record_id>` 收编既有 Issue，再用 GitHub 的明确终态回写飞书，不会重复建单。

## 状态映射规则

**仓库里只用「问题归属」一种标签**，等级/状态/信息写在 Issue 正文表格里；`Bug` 由 Issue Types 表达。

| 归属标签 | 飞书「问题归属类型」 | 责任人 |
| --- | --- | --- |
| `前端` | 前端 | 马园园 |
| `后端` | 后端 / 服务端 / 数据处理平台 | 李会会、柴金星 |
| `固件` | 固件嵌入式 | 宋冬冬 |
| `产品` | 产品 | 宋晓迪 |

### 飞书 → GitHub

| 飞书 | GitHub 结果 |
| --- | --- |
| 验证结果含「验证PASS / 复测通过」 | 状态=`关闭`，Issue 关闭（completed） |
| 研发归属类=非问题，或验证结果=非问题 | 状态=`关闭` + 信息=`非问题`，关闭（not_planned） |
| 研发归属类=重复问题 | 状态=`关闭` + 信息=`重复问题`，关闭（not_planned） |
| 研发归属类=未修复-无法修复 | 状态=`关闭` + 信息=`无法解决`，关闭（not_planned） |
| 研发归属类含「已修复」，或验证结果=待验证 | 状态=`已解决`，Issue 保持开启 |
| 研发归属类=需求未明确需产品确认 | 状态=`开放`，保持开启 |
| 其他（待修复、暂不处理…） | 状态=`开放`，保持开启 |
| 问题归属类型=前端/后端/数据处理平台/固件嵌入式 | 打 `前端`/`后端`/`采集平台`/`固件` 标签（产品、待确认不打） |

### GitHub → 飞书（研发在上面打结果）

| GitHub 动作 | 回写飞书 |
| --- | --- |
| 打 `非问题` | 研发归属类=非问题，验证结果=非问题 |
| 打 `重复问题` | 研发归属类=重复问题 |
| 打 `无法解决` | 研发归属类=未修复-无法修复，验证结果=暂不处理 |
| 打 `已解决` | 研发归属类=已修复-待验证，验证结果=待验证 |
| 打 `关闭` | 验证结果=验证PASS |
| 打 `开放` | 原为已修复→未修复-暂不处理；原验证通过/待验证→待修复 |
| 直接关单、没打任何状态标签 | 验证结果=验证PASS（沿用历史口径） |
| 改 `P0`~`P3` | 回写 BUG级别 |

> 研发只动标签和开/关，不要改正文——正文每轮由飞书覆盖。信息类标签（非问题/重复问题/无法解决）优先级最高，会直接关单。

## 冲突规则

- **内容冲突**（飞书改了描述、GitHub 改了正文）：以飞书为准，GitHub 正文被覆盖。
  → 所以在 GitHub 上不要直接改正文，评论里补充信息。
- **状态冲突**（两边都改了状态）：以 GitHub 为准，回写飞书。
- 回写时只写「与飞书现值不同」的字段，避免无谓改动记录。

## 运行方式

```bash
# 在云主机上、仓库目录内
python3 tools/woofen_sync.py            # 真正同步一轮
python3 tools/woofen_sync.py --dry-run  # 只看会做什么，不写入
```

- 运行需要：`gh` 已登录该账号（本机已配置）、飞书访问令牌（由会话注入，脚本内不存任何密钥）。
- 幂等：同一轮重复执行不会重复建单；`--dry-run` 不写入任何一侧。
- 状态文件：`/home/user/Doubao/chats/38454352490236674/.woofen-sync/state.json`，日志同目录 `sync.log`。
- 并发保护：脚本带 `flock`，上一轮未结束时本轮直接跳过。

## 已知限制

- 采用**轮询**方式（平台定时任务每小时跑一轮），不是实时 webhook：飞书改完到 GitHub 生效最多约 1 小时，反之亦然。
- 若要秒级实时，需要飞书**自建应用**的 `app_id/app_secret`（多维表格读写权限）+ GitHub PAT 互相回调，或加一个 GitHub Actions 工作流；当前方案不依赖任何需长期保存的密钥。
- GitHub 新建的、非飞书来源的 Issue（正文无 `woofen-sync` 标记）不会被同步。
